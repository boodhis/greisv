🔩 Heltec V3 / ESP32

Heltec V3 — ESP32-S3 с LoRa-радио. Как провести данные по радио в домашнюю инфраструктуру через MQTT-мост.

Зачем

У нас есть панель Heltec V3: ESP32-S3 с LoRa-радио, экран и кнопки — та самая, что хранит интервалы слов (2·5·10·25·60…) и кормит виджет «Слово дня» на главной. Но данные по радио ещё нужно провести в домашнюю инфраструктуру: Home Assistant, Navidrome, SOPDS, базы. Мост между LoRa и IP — это MQTT-брокер.

Heltec V3 (LoRa) → Шлюз (Raspberry Pi / ESP32) → MQTT-брокер (Mosquitto) → Подписчики (HA, скрипты, сайт)

Схема потока

┌─────────────┐ LoRa ┌─────────────┐ UART ┌─────────────┐ │ Heltec V3 │ ─────→ │ Шлюз │ ─────→ │ Raspberry Pi│ │ (сенсор) │ │ (Heltec V3) │ │ (bridge) │ └─────────────┘ └─────────────┘ └──────┬──────┘ │ MQTT publish ▼ ┌─────────────┐ │ Mosquitto │ └──────┬──────┘ ┌──────────────┼──────────────┐ ▼ ▼ ▼ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ HA │ │ Скрипт │ │ Сайт(SRS)│ └──────────┘ └──────────┘ └──────────┘

Публикация с Heltec V3 (PubSubClient)

#include <WiFi.h>
#include <PubSubClient.h>

const char* ssid = "your_wifi";
const char* password = "your_pass";
const char* mqtt_server = "192.168.1.100";
const int   mqtt_port = 1883;
const char* mqtt_user = "iot-client";
const char* mqtt_pass = "your_mqtt_pass";

WiFiClient espClient;
PubSubClient client(espClient);

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  client.setServer(mqtt_server, mqtt_port);
  client.setKeepAlive(60);
}

void reconnect() {
  while (!client.connected()) {
    if (client.connect("HeltecV3-Node", mqtt_user, mqtt_pass)) {
      client.subscribe("heltec/control");
    } else {
      delay(5000);
    }
  }
}

void loop() {
  if (!client.connected()) reconnect();
  client.loop();
  float temp = readTemperature();
  char payload[64];
  snprintf(payload, sizeof(payload), "{\"temp\": %.2f, \"unit\": \"celsius\"}", temp);
  client.publish("heltec/node1/sensor", payload);
  delay(30000);
}

Три обязательных пункта: setKeepAlive(60), client.loop() в каждом цикле и client.subscribe() — без него принимаются только публикации, но не команды.

Форматы вывода

ФорматКодПолучается
Плоский текстclient.publish("heltec/node1/temp", String(temperature).c_str())22.50
JSONsnprintf(..., "{\"temp\": %.2f, \"hum\": %.1f, \"bat\": %d}", temperature, humidity, batteryLevel){"temp": 22.50, "hum": 45.1, "bat": 98}
Компактный бинарьупаковать в uint8_t payload[4]4 байта вместо ~50 (экономия LoRa до 90%)
 
uint8_t payload[4];
payload[0] = (int)temperature;                 // целая
payload[1] = (int)(temperature * 10) % 10;     // десятые
payload[2] = (int)humidity;
payload[3] = batteryLevel;
client.publish("heltec/node1/sensor", payload, 4);

Приём на сервере

Bash:

mosquitto_sub -h localhost -t "heltec/+/sensor" -F "%t %p" | while read topic payload; do
  echo "[$(date)] $topic → $payload"
done

Python (paho-mqtt):

import paho.mqtt.client as mqtt, json

def on_message(client, userdata, msg):
    data = json.loads(msg.payload)
    print(f"{msg.topic}: temp={data['temp']}, hum={data['hum']}")

client = mqtt.Client()
client.username_pw_set("iot-client", "your_pass")
client.on_message = on_message
client.connect("localhost", 1883)
client.subscribe("heltec/+/sensor")
client.loop_forever()

Если Heltec висит по UART на Raspberry Pi — шлюзом служит скрипт serial_to_mqtt.py (читает порт, публикует в Mosquitto).

Плата Heltec V3 — старт

Heltec WiFi LoRa 32 V3 на чипе ESP32-S3: много GPIO, WiFi, LoRa, BLE, OLED-экран и кнопка. Наш сервер собирает для неё прошивку через ESPHome (конфиг → C++ → бинарь).

Пины (то, что задействовано у нас)

ПинЧто
GPIO0кнопка PRG (вход в прошивку / пользовательская кнопка)
GPIO35встроенный LED (status_led)
GPIO36питание OLED (inverted)
GPIO17/18I2C SDA/SCL (OLED)
GPIO21OLED reset
GPIO8/9/14SPI для LoRa (SX1262)

Полная карта пинов — в официальной доке (скачана локально на сервер: /var/www/html/panel/wiki/).

Прошивка по USB

  1. Кабель type-C с данными (не зарядный!) → плата = /dev/ttyUSB0 (чип Silicon Labs CP210x).
  2. Веб-инструмент панели /panel/: правишь server-panel.yaml → Скомпилировать → Прошить.
  3. Если плата «зависла» — удерживай PRG (GPIO0) и нажми сброс.
/home/iva/esphome/bin/esphome run /home/iva/server-panel/server-panel.yaml

Важно

Не выдёргивай кабель во время прошивки — можно убить загрузчик.

Наш конфиг server-panel.yaml: плата heltec_wifi_lora32_v3 (esp32s3, esp-idf); WiFi TP-Link_B31D_2_4; MQTT-брокер 192.168.0.244; text_sensor читает server/status; display — SSD1306 128×64, шрифт Press Start 2P; esp32_ble_server отдаёт статус по Bluetooth (характеристика + notify); binary_sensor GPIO0 → запрос статуса; switch — питание OLED (GPIO36).

Основы ESPHome

ESHome — когда пишут про ESPHome, имеют в виду подход: описываешь железо на YAML, а ESPHome собирает полноценную прошивку на C++. Меняешь поведение — правишь несколько строк yaml, а не сотни строк кода.

yaml-конфиг → компилятор → firmware.bin → залить на плату

Основные секции конфига

СекцияРоль
esphome:имя, friendly_name
esp32:плата (board, variant, framework)
wifi:подключение к сети
mqtt:обмен данными с сервером (брокер)
text_sensor: / sensor:чтение данных
display:экран, рисуем через lambda
switch: / binary_sensor:выходы / кнопки
esp32_ble_server:Bluetooth

Lambda — секретная сила

Там, где yaml не хватает, вставляют lambda — кусок C++ прямо в конфиг. Пример — наш display.lambda: строки статуса на OLED, шрифт Press Start 2P.

Совет

Когда учишься — сравнивай server-panel.yaml с докой по компоненту: как поля совпадают, так и собирается пазл.

Дока скачана локально на сервер: /var/www/html/panel/wiki/ — GPIO, WiFi, MQTT, Switch, Binary Sensor, SSD1306 (OLED), CLI.

Прототипирование: метод и идеи

Метод (как учиться быстрее всего):

  1. Читай один раздел за раз (пины → прошивка → ESPHome → компоненты).
  2. Меняй конфиг: одна маленькая вещь за раз → компилируй → прошивай.
  3. Смотри на плату: что изменилось (LED, OLED, MQTT).
  4. Ломай осознанно и чини по логу компиляции.

Главный принцип

Маленький шаг → компиляция → проверка. Не меняй много за раз.

Уже умеем на этой плате: статус сервера по MQTT → на OLED; уведомление по BLE (телефон видит плату); кнопка на плате → запрос статуса.

Идеи, что добавить (по возрастанию сложности):

  • Кнопка-действие (перезапуск службы, тумблер)
  • Датчик температуры/влажности (DHT22) → в MQTT
  • Светодиодная индикация по статусу сервера
  • Вторая экранная страница на OLED (кнопка перелистывает)
  • LoRa-сообщение на вторую плату (радио без WiFi)
  • Счётчик аптайма сервера (в свою BLE-характеристику)
Прототипирование = собрать → подключить → прошить → протестировать. Всё это уже покрыто инструментом /panel/.

Meshtastic на Heltec V3

Meshtastic — прошивка, превращающая Heltec V3 в узел автономной LoRa-меш-сети (сообщения и координаты без интернета, ноды связываются между собой по радио). Три способа прошить:

СпособКому подходитКоманда
Meshtastic Flasherновичкам (GUI, есть кнопка Full Erase, сама качает прошивку)с официального сайта Meshtastic
esptoolиз терминала, разовый перенос `firmware.bin`pip install esptool → esptool.py --chip esp32s3 --baud 921600 write_flash 0x0 firmware-heltec-v3-2.5.x.bin
Meshtastic CLIнастройка и обновления по сетиpip install meshtastic → meshtastic --flash
VS Code + PlatformIOкопаться в исходниках прошивки под себяоткрыть проект, выбрать профиль heltec_v3, Build → Upload

Совет

PlatformIO умеет и «чистить» плату (Erase Flash) перед заливкой — это как Full Erase у Flasher. Для версии из исходников собери под себе подходящий S3-чип: выбор профиля в нижней синей панели.
