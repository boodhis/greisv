# Инструкция по вёрстке — Цифровая Крепость

Сайт — это **обычные HTML-файлы** в этой папке (`/home/iva/greisv`), никаких сборщиков и фреймворков.
Правишь файл → сохраняешь → `git push` → GitHub Pages сам обновляет сайт.

> Синхронизация из Obsidian (автоген `gen_vault.py`) **отключена**. Все страницы правятся здесь, прямо в HTML.

## Как устроен сайт

```
greisv/
├── index.html            ← главная (шапка + сетка карточек разделов)
├── manifest.html         ← манифест
├── style.css             ← общие стили (для новых статей)
├── sw.js                 ← офлайн-кеш + список страниц (ASSETS)
├── sitemap.xml           ← карта сайта для поисковиков
├── getting-started/      ← раздел «С чего начать»
├── study/                ← обучение: тренажёр (SRS), шпаргалки
├── electric/             ← электрика (генерит gen/gen_electric.py)
├── homelab/              ← homelab-статьи
├── services/             ← сервисы
├── guides/               ← гайды
├── resources/            ← ресурсы
├── hobbies/              ← досуг
└── gen/                  ← генераторы (deck/electric/icons)
```

- **Папка = раздел**, файл `x.html` = страница `https://boodhis.github.io/greisv/x.html`.
- **Главная и манифест** — в корне, остальные — в подпапках.
- Внутри каждой папки может быть свой `index.html` — страница раздела.

## Типовая страница статьи

```html
<!DOCTYPE html>
<html lang="ru">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Название — Цифровая Крепость</title>
<meta name="description" content="Описание для поиска и OG">
<link rel="icon" type="image/svg+xml" href="../favicon.svg">  <!-- ../ в подпапках, в корне просто favicon.svg -->
<link rel="stylesheet" href="../style.css">                     <!-- если пользуешься общими стилями -->
</head>
<body>
<div class="layout">
<aside>   <!-- боковое меню не всегда: в новых страницах вместо него верхняя рамка .fnav (см. ниже) -->
</aside>
<main>
<h1>Название статьи</h1>
<p class="desc">Короткое описание под заголовком</p>

<p>Текст абзаца.</p>
<h2>Подзаголовок</h2>
<ul>
<li>пункт 1</li>
<li>пункт 2</li>
</ul>
<pre><code>sudo systemctl status nginx</code></pre>
</main>
</div>
</body>
</html>
```

### Общие стили (`style.css`)
Если страница подключает `style.css`, доступны:
- `class="callout"` → блок-справка. Варианты: `callout-note`, `callout-warning`.
- `class="grid"` + `class="card"` → сетка карточек (см. главную).
- `h1 h2 h3 p ul ol pre code table` — уже оформлены.
- `class="desc"` — подзаголовок-описание.

### Верхняя рамка навигации (fnav) — у современных страниц
Вместо бокового меню — рамка вверху:


## После правки

1. Проверь глазами в браузере.
2. Прогони тесты, чтобы ничего не сломалось:
   ```bash
   python3 tests/test_site.py
   ```
3. Если добавил **новую** страницу — впиши её в три места:
   - `sw.js` → список `ASSETS` (и подними `var CACHE = "fortress-v14";` → v15 => клиент обновится);
   - `sitemap.xml` → добавь `<url>`;
   - если есть блок «Связанные страницы» на странице раздела — добавь ссылку.
   После этого тесты `test_sw_precache_covers_all_pages` и `test_sitemap_covers_all_pages` обязаны пройти.
4. Коммит и пуш (сайт обновится за ~1 минуту):
   ```bash
   git add -A && git commit -m "Название" && git push
   ```

> Примечание: `study/` (тренажёр SRS) и `electric/` (электрика) имеют свои генераторы (`gen/gen_deck.py`, `gen/gen_electric.py`) — их не трогают руками, кроме карточек.

## Частые приёмы

- **Ссылка на другую страницу**: `<a href="../services/navidrome.html">Navidrome</a>` (относительно папки текущей страницы).
- **Внешняя ссылка**: `<a href="https://...">…</a>`.
- **Карточка в сетке**:
  ```html
  <div class="grid">
  <div class="card"><h4>Заголовок</h4><p>Текст.</p></div>
  </div>
  ```
- **Спойлер/вкладка**: обычный `<details><summary>…</summary>…</details>`.
- **Виджет «Слово дня»** на страницах:
  ```html
  <div id="wordday" style="display:none"></div>
  <script src="study/data/wordday.js"></script>
  ```

Если сомневаешься — открой соседнюю похожую страницу в этом репозитории и сделай по её шаблону.
