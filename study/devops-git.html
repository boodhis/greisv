Обучение

Git: init, ветки, коммиты, remote, merge и rebase — дневной цикл разработчика.

Git — не «сохранение версий», а инструмент мышления о коде: ветки, история, откат. Без него ни CI, ни деплой, ни командная работа. Здесь — база и типичный дневной цикл.

Инициализация и первый коммит

git init
git config user.name "Иван"
git config user.email "ivan@app.local"
git add .
git commit -m "первый коммит"

Ветки

git branch                       # список
git switch -c feature/vpn        # создать и перейти
git switch main                  # вернуться
git branch -d feature/vpn        # удалить после мержа

Remote

git remote add origin git@git.app.local:me/project.git
git push -u origin main
git pull

Merge и rebase

Merge сохраняет историю ветвления, rebase переносит коммиты на свежую базу — линейно и чище, но переписывает историю. На общей ветке rebase не делай.

# merge
git switch main
git merge feature/vpn

# rebase своей ветки на свежий main
git switch feature/vpn
git rebase main

Дневной цикл

  1. git pull — подтянуть чужие изменения.
  2. git switch -c feature/x — новая ветка под задачу.
  3. Правишь код, проверяешь.
  4. git add -p — складываешь в индекс только осмысленные куски.
  5. git commit -m "..." — мелкий понятный коммит.
  6. git push -u origin feature/x.
  7. Merge request / pull request, ревью, merge в main.

Отмена

ЗадачаКоманда
Отменить правки файлаgit restore file
Убрать из индексаgit restore --staged file
Поправить последний коммитgit commit --amend
Откатить коммит, сохранив историюgit revert <sha>
Спрятать правкиgit stash / git stash pop
Коммит — это единица смысла

Один коммит — одно изменение. «Починил всё» не пройдёт ревью и не откатится.
