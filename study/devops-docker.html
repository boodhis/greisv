Обучение

Docker: образы, контейнеры, Dockerfile и docker-compose — типичный стек.

Docker упаковывает приложение со всеми зависимостями в образ. Один и тот же контейнер работает на ноутбуке и на сервере — исчезает «у меня запускается». Здесь: образы, контейнеры, Dockerfile, compose.

Образы и контейнеры

docker pull nginx:alpine
docker images
docker run -d --name web -p 8080:80 nginx:alpine
docker ps
docker logs -f web
docker exec -it web sh
docker stop web && docker rm web

Образ — шаблон, контейнер — запущенный экземпляр. Данные внутри контейнера живут до удаления — для сохранения нужен volume.

Dockerfile

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .

EXPOSE 8000
CMD ["python", "-m", "app"]

Собирай и запускай:

docker build -t app:0.1 .
docker run -d --name app -p 8000:8000 app:0.1

Порядок слоёв важен: COPY requirements.txt до COPY . ., тогда кэш зависимостей не сбрасывается на каждую правку кода.

Volumes и сеть

docker run -d \
    -v /srv/app/data:/data \
    --network appnet \
    --name app app:0.1

docker-compose

services:
  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      DB_HOST: db
    depends_on:
      - db
    volumes:
      - ./data:/data

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
docker compose up -d
docker compose logs -f
docker compose down

Не запускай всё от root на хосте

Создай пользователя и добавь в группу docker. Но помни: членство в группе docker = root на хосте. На критичных машинах используй rootless-режим.
