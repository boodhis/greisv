⚙️ Разработка приложений под Linux

Второй курс. Ты уже знаешь основы Python (или прошёл первый курс) — теперь учишься делать из скрипта настоящую программу: сначала простая утилита, потом командная, потом с окном, а в конце — сервис, который живёт на сервере сам. Всё на твоём хомлабе, по одному модулю за раз.

Как устроен курс

Путь: скрипт → CLI → GUI → сервис. Каждый модуль — одна идея + задание. Сквозной проект — «Счётчик расходов»: считалка, которая растёт из консольной тулзы в программу с окном, а под конец становится сервисом, который пишет отчёт раз в день. ИИ-наставник — рядом в каждом модуле.

Модуль 1 · От скрипта к программе: структура и окружение

Цель: понять разницу «скрипт» и «приложение», настроить окружение проекта.

Скрипт — файл, который делает одну работу. Программа — то же плюс: папка проекта, понятные имена, возможность запуска «по правилам» Linux (права, вывод сообщений, обработка ошибок). Минимум структуры для Python-проекта:

expenses/           ← папка проекта
├── expenses.py     ← главный файл (логика)
└── data/           ← папка для данных (создадим)

Начни с правильной настройки: Python 3 уже есть на сервере (python3 --version). Для чистоты проекта создают виртуальное окружение — «коробку», где живут только библиотеки этого проекта (современный инструмент — uv, спроси ИИ, как поставить).

cd ~/expenses
uv venv                # если поставил uv
source .venv/bin/activate
python3 --version
Задание 1. Создай папку проекта, поставь uv, создай окружение. В expenses.py сделай первую версию: та же функция, что в модуле 1 курса Python — печать приветствия и «готов к работе». Запусти так, чтобы увидел свой код.
Спроси ИИ: «Зачем виртуальное окружение и что оно решает?» И «Поставь мне uv и проведи по созданию окружения по шагам».

Модуль 2 · Скрипт, который полезен сам по себе

Цель: автоматизировать скучную задачу и не бояться отдельных кусков.

Приложение начинается с того, что ты делаешь задачу, которую вручную делал много раз. У «Счётчика расходов» первая ценность — чтение и учёт: ты записываешь траты в файл, скрипт их считает. Работа с путями и файлами — через pathlib (безопасно и по-современному).

from pathlib import Path
import json

data_dir = Path.home() / "expenses" / "data"
data_dir.mkdir(exist_ok=True)
файл = data_dir / "spend.json"

# Если файла нет — начнём с пустого списка
список = []
if файл.exists():
    список = json.loads(файл.read_text("utf-8"))

трата = {"что": "кофе", "сумма": 150, "день": "2026-09-21"}
список.append(трата)
файл.write_text(json.dumps(список, ensure_ascii=False, indent=2), "utf-8")
print("Записал трату. Всего:", len(список))
Задание 2. Доведи скрипт до «считалки»: после добавления печатай сумму всех трат и число записей. Проверь, что файл создаётся, данные переживают перезапуск.
Спроси ИИ: «Что делает json.dumps(..., indent=2)?» и «Как добавить запись, не затирая старые?» — прежде чем спросить, попробуй сам.

Модуль 3 · CLI: у программы появляются команды и флаги

Цель: запускать программу как «настоящую», с аргументами и --help.

CLI-приложение — программа из терминала с осмысленными командами: expenses add 150 кофе и expenses total. Аргументы разбирает argparse — он же генерирует справку. Коды выхода: 0 — всё ок, не 0 — ошибка.

import argparse

p = argparse.ArgumentParser(description="Счётчик расходов")
sub = p.add_subparsers(dest="cmd", required=True)

add = sub.add_parser("add", help="добавить трату")
add.add_argument("--сумма", type=int, required=True)
add.add_argument("--что", required=True)

total = sub.add_parser("total", help="сумма всех трат")

args = p.parse_args()
if args.cmd == "add":
    print(f"Записал: {args.что} на {args.сумма} р.")
if args.cmd == "total":
    print("Считаю сумму...")
Задание 3. Доведи две команды до рабочих: add реально дописывает трату в файл, total печатает сумму. Проверь --help. Сделай команду top — самая крупная трата.
Спроси ИИ: «Покажи, как argparse ловит ошибки ввода» и «Проверь мой CLI-код: что не так, без исправлений».

Модуль 4 · GUI: у программы появляется окно

Цель: собрать то же приложение с кнопками и списком, не раздувая код.

GUI = окно с элементами: кнопки, поля, списки. Начинать стоит с Tkinter (входит в Python, ничего не ставится). На сервере без экрана окно не покажешь — поэтому этого модуля запускаем на своём компе либо на сервере с удалённым рабочим столом. Логику (работу с файлом) НЕ переписываем: GUI лишь вызывает те же функции.

import tkinter as tk

root = tk.Tk()
root.title("Счётчик расходов")

label = tk.Label(root, text="Сколько потрачено?")
label.pack(pady=10)
info = tk.Label(root, text="")
info.pack()

def показать_сумму():
    # здесь вызываешь свою функцию из expenses.py
    info.config(text="Сумма посчитается здесь")

кнопка = tk.Button(root, text="Показать сумму", command=показать_сумму)
кнопка.pack(pady=10)
root.mainloop()
Задание 4. Сделай окно с: полем ввода суммы, кнопкой «Добавить», кнопкой «Сумма», меткой с результатом. Используй логику из модулей 2–3 — окно вызывает её.
Спроси ИИ: «Что делает mainloop() и почему программа "висит", пока окно открыто?» Продолжи: «Чем tkinter.Tk отличается от окна "взрослого" приложения на GTK/Qt?» — это подведёт к модулю 6.

Модуль 5 · Сервис: программа, которая живёт на сервере сама

Цель: приложение работает без человека — как демон под systemd.

Сильнее всего Linux любит сервисы: программу заворачивают в systemd-юнит, и она стартует при загрузке, перезапускается при падении, пишет в журнал. Из «Счётчика» сделаем сервис, который раз в день добавляет напоминание или пишет отчёт дня в журнал.

Файл юнита /etc/systemd/system/expenses.service:

[Unit]
Description=Счётчик расходов: дневной отчёт
After=network.target

[Service]
ExecStart=/home/iva/expenses/.venv/bin/python /home/iva/expenses/report_daily.py
Restart=on-failure
User=iva

[Install]
WantedBy=multi-user.target

Затем включаем демон и смотрим, работает:

sudo systemctl daemon-reload
sudo systemctl enable --now expenses
systemctl status expenses
journalctl -u expenses -f        # журнал сервиса
Задание 5. Напиши report_daily.py (считает сумму трат за сегодня и пишет строку в журнал). Создай юнит, включи, проверь статус и журнал. Останови сервис и пойми, почему — до того как чинить.
Спроси ИИ: «Объясни каждую строчку юнита с точки зрения новичка» и «Юнит не стартует: journalctl показывает ошибку — помоги прочитать» (не «исправь»).

Модуль 6 · Жизнь в дистрибутиве: упаковка и запуск

Цель: сделать программы «устанавливаемой» и понятной, как у больших приложений.

Настоящее приложение в Linux умеет: запускаться из меню (.desktop-файл), устанавливаться (.deb) и работать без «магии». Быстрый вход — .desktop для CLI/GUI программы, народный формат знакомства — собрать свой первый пакет. Для GUI-версии .desktop-файл:

[Desktop Entry]
Type=Application
Name=Счётчик расходов
Exec=python3 /home/iva/expenses/gui.py
Path=/home/iva/expenses
Terminal=false
Categories=Utility;

Современная альтернатива для «красивого окна» — Tauri (веб-UI, Rust-ядро, собирает .deb/AppImage одной командой) и GTK/Qt для «настоящих» нативных программ. Для первого года жизни Tkinter более чем достаточно.

Задание 6 (финал). Расположи .desktop-файл так, чтобы программа появилась в меню, и запусти её оттуда. Собери CLI-версию в .deb (попроси ИИ дать минимальный набор: папка с content — и dpkg-deb --build). Установи и запусти.
Спроси ИИ: «Что такое AppImage и Flatpak простыми словами?» и «Дай мне план: как из моего скрипта сделать настоящий установщик и не утонуть».
