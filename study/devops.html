🧭 DevOps с нуля до Junior

Устраиваемся Junior DevOps инженером за 4–6 месяцев при занятиях 1–2 часа в день. Честный план: что спрашивают на собеседовании, что учить по месяцам, какие проекты делать в портфолио. Вся практика — на своём подопытном сервере (хомлабе), вся учёба — в паре с ИИ-наставником.

Три правила курса

1. Одна тема — один день, повторение через день-два (карточки «слова дня»). 2. Каждый модуль заканчивается чекпоинтом — ты что-то реально запустил. 3. Застрял — идёшь по методу починки (ниже) и зовёшь ИИ-наставника; он не даёт готовый ответ, а ведёт шагами.

План по месяцам

Месяц 1 · Фундамент: Linux + Bash + Git

Команды: ls cd cat grep tail ps kill chmod chown systemctl journalctl. Учимся писать первый скрипт. Git: репозиторий, ветки, пул-реквесты.

Чекпоинт: скрипт, который раз в 5 минут проверяет место на диске и пишет в лог.

Месяц 2 · Docker

Образы, контейнеры, volumes, сети; свой Dockerfile (Python/Node); Compose: WordPress (nginx+php+mysql+phpmyadmin) одной командой.

Чекпоинт: WordPress в docker-compose, поднятый одной командой.

Месяц 3 · CI/CD + GitLab

.gitlab-ci.yml; пайплайн lint → test → build → push; деплой на сервер по SSH/Docker.

Чекпоинт: пуш → автосборка образа → автодеплой.

Месяц 4 · Мониторинг + Cloud

Prometheus + Grafana в Compose; метрики сервера; алерты в Telegram; VM в облаке (Yandex/AWS free tier), Docker + деплой.

Чекпоинт: дашборд Grafana с CPU/RAM/Disk.

Месяц 5–6 · Проект + собеседования

Портфолио на GitHub (3–4 проекта), LinkedIn/HH.ru, 3–5 технических собеседований.

Проекты для портфолио (обязательно)

  1. Простейший: статический сайт на Nginx в Docker.
  2. Средний: WordPress в Docker Compose с volume для данных.
  3. Сложнее: Todo (React + Node + PostgreSQL) в Compose + CI/CD в GitLab.
  4. Прокачка: то же приложение + Prometheus + Grafana + алерты.

Ключевые концепции (запомнить)

  • Образ (Image) — рецепт/чертёж для создания контейнера.
  • Контейнер (Container) — запущенный экземпляр образа.
  • Volume — проброс папки между хостом и контейнером.
  • Port mapping (-p) — задаётся ТОЛЬКО при создании (docker start его не меняет).
  • docker-compose.yml — описание группы контейнеров.
  • Пользовательская сеть Docker — даёт DNS: контейнеры общаются по именам.
  • Обратный прокси (nginx) — принимает внешние запросы и перенаправляет во внутреннюю сеть (proxy_pass).
  • IaC — не запускаем руками, пишем «рецепт» в YAML и держим в Git.
  • Resource limits — «забор» для процессов, чтобы контейнер не съел весь хомлаб.

Метод починки сервера (факты → логи → гипотеза → проверка → фикс → запись)

«Не работает» почти никогда не значит «сломалось» — это значит «надо найти, где порвалась цепочка». Правильный порядок:

СИМПТОМ → ФАКТЫ → ЛОГИ → ГИПОТЕЗА → ПРОВЕРКА → ФИКС → ЗАПИСЬ
(что именно    какая ошибка    systemctl,      одна,     дешёвая   минимальный   что было,
  сломалось)   когда, что       journalctl,    самая      команда   и обратимый    почему,
               менялось        ss -tlnp        простая    да/нет                чем починил
Спроси ИИ: «Сервис не работает. Какую первую команду запустить и что она покажет?» — и пусть наведёт на метод, а не даст ответ. Правило: ИИ показывает как искать, а не что нажать.

Шпаргалка разведки (команда → что узнаю)

СитуацияКомандаЧто узнаю
«Сервис не работает»systemctl status <имя>статус, ошибку, последние строки лога
«Что он логгирует»journalctl -u <имя>весь журнал сервиса
«Сайт не открывается»systemctl status nginx + логжив ли nginx, что ругается
«Порт занят/никакой»ss -tlnpкто на каких портах слушает
«Место кончилось»df -hзанятость дисков
«Что-то грузит CPU»ps aux / topпроцессы, нагрузка
«Где мой процесс»ps aux | grep <имя>жив ли процесс, его PID
«Контейнер молчит»docker ps + logsзапущен ли, что пишет

Практика на живом стеке (важные уроки)

  • Проброс порта задаётся при создании контейнера; docker start параметры не меняет.
  • Docker-сеть по умолчанию (bridge) изолирована: внутри неё может не быть выхода в интернет.
  • docker exec -it <имя> bash — зайти внутрь; docker logs <имя> — понять, почему упал.
  • nginx внутри контейнера не стартует сам при docker start — запускать вручную через exec.
Куда дальше
