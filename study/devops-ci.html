Обучение

CI/CD на GitHub Actions: workflow, триггеры, джобы и деплой на сервер по ssh.

CI — автоматическая проверка каждого коммита: тесты, линтер, сборка. CD — автоматический деплой после проверки. Руками это делать больно, поэтому — GitHub Actions (или GitLab CI).

Понятия

  • workflow — файл .github/workflows/*.yml.
  • job — набор шагов, выполняется на отдельной машине.
  • step — один шаг: команда или готовый action.
  • trigger — событие, по которому запускается workflow.

Триггеры

on:
  push:
    branches: [main]
  pull_request:
  schedule:
    - cron: "0 3 * * *"
  workflow_dispatch:

Пример workflow

name: ci

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pytest -q

  deploy:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: deploy
        env:
          SSH_KEY: ${{ secrets.SSH_KEY }}
        run: |
          mkdir -p ~/.ssh
          echo "$SSH_KEY" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          ssh-keyscan app.local >> ~/.ssh/known_hosts
          ssh deploy@app.local 'cd /srv/app && git pull && docker compose up -d --build'

Секреты и окружения

Ключи и пароли — только в Settings → Secrets, в репозитории их нет. Окружения (environments) дают отдельные секреты для staging и prod и ручное подтверждение деплоя.

Что проверять в CI

  1. Установка зависимостей — ловит битый requirements.
  2. Линтер (ruff, shellcheck) — стиль и явные ошибки.
  3. Тесты (pytest) — поведение.
  4. Сборка образа — Dockerfile живой.
  5. Деплой — только на main и только после зелёного теста.
Быстрый фидбек

Сначала лёгкие шаги (линтер), потом тяжёлые (тесты, сборка). Разработчик узнаёт об ошибке за минуту, а не за десять.

Не деплой без ревью

Автодеплой с push в main — удобно, но добавь защиту ветки: PR + зелёный CI. Иначе одна опечатка уйдёт в прод.
