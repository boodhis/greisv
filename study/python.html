🐍 Python с нуля на реальном проекте

Это не абстрактные примеры, а наш живой проект «Библиотека» — веб-морда над каталогом книг (~400 тысяч). Ты видишь код, который реально работает на homelab, и задания: сначала читаешь и разбираешь, потом делаешь своё.

Как устроен проект

Стек: Python 3 + FastAPI (веб-фреймворк) + Jinja2 (шаблоны) + PostgreSQL (база книг) + psycopg2 (драйвер БД). Весь сервер — один файл app.py. В каждом модуле ниже мы берём настоящий кусок из него.

Модуль 1 · Переменные, функции, циклы

Самый частый приём в проекте — «взять значение из БД, преобразовать, вставить в HTML». Начнём с маленькой функции, которая превращает число байт в человеческий размер:

def fmt_size(b):
    if not b:
        return ""
    n = float(b)
    for unit in ("B", "КБ", "МБ", "ГБ"):
        if n < 1024 or unit == "ГБ":
            return f"{n:.1f} {unit}" if unit != "B" else f"{int(n)} {unit}"
        n /= 1024
    return f"{n:.1f} ГБ"

Здесь сразу несколько базовых вещей:

  • Аргумент и возврат. Функция получает b и возвращает строку.
  • Условие if not b — срабатывает на None, 0, пустую строку (в Python это «ложные» значения).
  • Цикл по кортежу с выходом через return — классический досрочный выход.
  • f-строки — подстановка значений и форматирование: {n:.1f} — один знак после запятой.

Модуль 2 · Словари и списки

Книги из базы приходят как списки словарей. В проекте каждый элемент дополняется полем для показа:

items = books_query(match=random_book_ids(12), only_ru=True, limit=12)
for it in items:
    it["size_fmt"] = fmt_size(it["filesize"])
  • Словарь — это «ключ → значение». Здесь в каждый dict добавляется новый ключ.
  • Список — упорядоченная коллекция; for it in items проходит по всем.
  • Такую же конструкцию можно записать короче — генератором списка (о нём ниже).

Модуль 3 · Работа с базой данных

Проект общается с PostgreSQL через курсор — объект, который выполняет SQL и возвращает строки:

cur = get_conn().cursor()
cur.execute(
    "SELECT id FROM opds_catalog_book WHERE lang = %s ORDER BY random() LIMIT %s",
    (LANG_RUS, size),
)
_pool["ids"] = [r[0] for r in cur.fetchall()]
cur.close()
  • Место для параметров — %s, значения передаются вторым аргументом. Никогда не подставляй пользовательский ввод прямо в SQL — это уязвимость «инъекция».
  • fetchall() возвращает список кортежей; r[0] — первый столбец.
  • r[0] for r in ... — генератор списка: компактный способ собрать новый список из другого.
Задание 3. Запрос с фильтром + счёт: выбери из таблицы opds_catalog_book все id книг автора (столбец author равен значению переменной), и посчитай, сколько их. Подсказка: COUNT(*) вернёт одно число.

Модуль 4 · Контекстные менеджеры

Открыть-использовать-закрыть — частая идиома. Python делает это красиво через with. В проекте курсор так и используется:

with get_conn().cursor() as cur:
    cur.execute("SELECT count(*) FROM opds_catalog_book WHERE lang = 'Русский'")
    total = cur.fetchone()[0]

Блок with гарантирует close() даже при ошибке. Для этого у объекта определены магические методы __enter__ и __exit__. В проекте даже сделана обёртка, которая возвращает соединение в пул:

class _PoolCursor:
    def close(self):
        self._pool.putconn(self._cur.connection)
        self._cur.close()
    def __enter__(self):
        return self
    def __exit__(self, *exc):
        self.close()

Модуль 5 · Веб: маршруты и шаблоны

FastAPI превращает функцию в веб-страницу декоратором @app.get(...). Параметр запроса q — это строка поиска из адреса:

@app.get("/search", response_class=HTMLResponse)
def search(request: Request, q: str = "", genre: str = "", ... ):
    items, page, pages = books_query(q=q, ...)
    ctx = {"q": q, "items": items, "page": page, "pages": pages}
    return templates.TemplateResponse(request, "_catalog.html", ctx)
  • Декоратор — функция, которая добавляет поведение другой функции (здесь — привязку к URL).
  • Аргумент request — FastAPI сам подставляет HTTP-запрос.
  • Шаблон — HTML-файл со вставками {{ q }}; словарь ctx — данные для подстановки.

Модуль 6 · Производительность и хитрости

Проект хранит ~400 000 книг, и «наивный» код не проходит. Главная отдаёт случайные книги — вместо ORDER BY random() по всей таблице (медленно) используется пул, который обновляется раз в 6 часов:

def _random_pool(size=2000):
    now = time.time()
    if _pool.get("ts") and now - _pool["ts"] < 6 * 3600 and _pool.get("ids"):
        return _pool["ids"]
    # ... один медленный запрос, результат закеширован в памяти
    _pool["ids"] = [r[0] for r in cur.fetchall()]
    return _pool["ids"]
  • Кеш в памяти — храним результат дорогого запроса и пересчитываем по таймеру.
  • Поиск %…% не использует обычные индексы — в проекте для скорости установлено расширение pg_trgm с GIN-индексом (поиск ускорился с 0.88 с до 0.14 с).
  • Измеряй, потом ускоряй — сначала план запроса, потом индекс, а не наоборот.
