📦 homelab-kit

Команда: «развернуть homelab без интернета». Один диск или скрипт — и на любой Ubuntu поднимается телега сервисов: Immich, Navidrome, SOPDS, Open WebUI, Ollama.

Что умеет кит
  • Ставить весь стек без интернета: Docker, Ollama, opencode — из статических бинарников.
  • Работать на любом systemd-дистрибутиве x86_64.
  • Загрузочный вариант: Ubuntu (сервер + GNOME) с авторазвёртыванием при первом старте.
  • Сам подбирает модель Ollama под железо клиента (CPU/RAM/GPU/VRAM).

Два способа развернуть

Вариант 1 — загрузочный диск (рекомендуется)

Готовый образ Ubuntu с автологином kit и сервисом первого старта, который сам ставит весь стек.

Подготовка (на своей станции)

# найти диск клиента (данные на нём сотрутся!)
lsblk -o NAME,SIZE,MODEL

# записать образ (device указывай точно!)
sudo dd if=ubuntu-kit.img of=/dev/sdX bs=4M status=progress

# расширить раздел на весь диск
sudo growpart /dev/sdX 3 && sudo resize2fs /dev/sdX3

Первый запуск у клиента

  1. Вставь SSD в компьютер клиента, загрузися с него (F12 / F2 / Del в BIOS).
  2. Ubuntu стартует с автологином пользователя kit.
  3. Автоматически отработает homelab-kit-firstboot.service: определит железо → поставит Docker/Ollama/opencode → смонтирует диски данных по UUID → загрузит образы → подберёт модель → запустит весь стек.
  4. Сервисы доступны: Immich :2283, Navidrome :4533, SOPDS :8081, Open WebUI :3000, Ollama :11434.

Вариант 2 — ручной деплой на существующей Ubuntu

Шаг 1. Скопировать кит

sudo cp -r /opt/homelab-kit /opt/homelab-kit   # откуда-нибудь на диск
# или: sudo cp -r ~/kit /opt/homelab-kit

Шаг 2. Настроить config.env

cd /opt/homelab-kit
sudo cp config.env.example config.env
sudo nano config.env

# UUID дисков данных (узнать через blkid)
DATA_DISK_UUID="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
LIB_DISK_UUID="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

# какие стеки ставить (через пробел)
STACKS="immich navidrome sopds open-webui"

Шаг 3. Запустить deploy

sudo bash /opt/homelab-kit/scripts/deploy.sh

Шаг 4. Проверить

docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
# http://localhost:2283 — Immich, :4533 — Navidrome, :8081 — SOPDS, :3000 — Open WebUI

Архитектура кита

kit/
├── images/               # docker save всех образов → docker load оффлайн
├── pkgs/                 # статические бинарники: docker.tgz, compose, ollama, opencode
├── ollama-models/        # модели (qwen3.5:9b, qwen3:14b, gemma4:12b, nemotron:24b, embedding)
├── stack/                # docker-compose (immich, navidrome, sopds, open-webui) + оверлеи
├── scripts/              # install-docker/ollama/opencode + главный deploy.sh
└── config.env.example    # параметры клиента (диски по UUID, стеки, порты)

Ключевые решения (почему так)

  • Оффлайн = самодостаточность. Образы — docker save | gzip; Docker — статические бинарники (без apt и зависимостей); Ollama — тарболл с CUDA-библиотеками; модели — в OLLAMA_MODELS. apt-get update вообще не вызывается.
  • Железо клиента неизвестно. deploy.sh сам определяет CPU/RAM/GPU/VRAM: Immich ML auto|cpu|cuda, модель Ollama подбирается по VRAM (nemotron → qwen3:14b → qwen3.5:9b → CPU-fallback), Open WebUI ходит на нативный Ollama 127.0.0.1:11434 (не docker-в-docker).
  • Диски — по UUID. Фото/музыка/библиотеки живут на дисках клиента: монтирование mount UUID → DATA_ROOT/LIB_ROOT.
  • Один скрипт на всё. probe железа → install runtime → mount → load образов → генерация .env → docker compose up -d → restore sopds → настройка opencode (offline AI).
  • Загрузочная версия. GPT: bios_grub + ESP + ext4(root), debootstrap noble + ubuntu-desktop-minimal (GNOME, автологин kit), systemd unit homelab-kit-firstboot.service. GRUB дважды: i386-pc (BIOS) + x86_64-efi --removable (UEFI без NVRAM).

Возможные проблемы

ПроблемаРешение
disk with UUID ... not foundsudo blkid — сверить UUID, обновить config.env
Docker не стартуетsudo systemctl start docker && docker info
Ollama не грузит модельollama list; если есть сеть — ollama pull <model>
Immich не видит фотоПроверить UPLOAD_LOCATION в .env — путь должен быть корректным
Нет доступа с другого устройстваПроверить порты в docker-compose.yml, bind должен быть 0.0.0.0
GRUB не видит дискВ BIOS выключить Secure Boot, включить CSM/Legacy (для BIOS-режима)
UEFI не загружаетсяSecure Boot выключен; EFI-раздел на месте (/boot/efi в образе)

Уроки/грабли (проверено вживую)

  • grub-pc и grub-efi-amd64 конфликтуют — ставить только -bin пакеты.
  • Том open-webui (~1G) снимается только через docker run --rm -v ... tar — каталог volume в /var/lib/docker не читается обычным юзером.
  • docker save хорошо жмёт: 7.1G open-webui → 1.7G tar.gz; сумма всех образов 6.8G.
  • Долгие pull больших образов — nohup docker pull, доверить демону.
  • loop-образ: после повторного losetup --partscan узлы разделов могут не создаться — выручает partprobe.
  • debootstrap: сначала minbase, потом apt-пакеты в chroot (mount proc/sys/dev). Образ нельзя переразмечать на лету в debootstrap.

Зачем это

Кит — «тёплый» резерв собственного homelab (весь стек+конфиги+БД перезапускаются одной командой) и материал для монетизации: развёртывание похожих систем за деньги в оффлайне. Учебные страницы по стеку — в разделах Сервисы и homelab.

Цифровая Крепость — образовательный сайт о Linux и homelab. Все примеры проверены на реальном сервере.
