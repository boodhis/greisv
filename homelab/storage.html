Хранилище

ZFS, RAID, контроль целостности и бэкапы.

Хранилище — фундамент homelab: бэкапы, медиа, данные VM. Если диск умрёт без копий, всё остальное неважно. Здесь — ZFS, снапшоты, скрабы, RAIDZ и правило 3-2-1.

ZFS: пул

sudo apt install zfsutils-linux

# один диск
sudo zpool create tank /dev/disk/by-id/ata-XXXX

# зеркало из двух дисков
sudo zpool create tank mirror \
    /dev/disk/by-id/ata-AAA \
    /dev/disk/by-id/ata-BBB

Используй by-id, а не /dev/sda: буквы меняются после перезагрузки.

Датасеты

sudo zfs create tank/data
sudo zfs create tank/backup
sudo zfs set compression=lz4 tank/data
sudo zfs set atime=off tank
zfs list

Снапшоты и скрабы

sudo zfs snapshot tank/data@2026-01-01
sudo zfs list -t snapshot
sudo zfs rollback tank/data@2026-01-01
sudo zfs destroy tank/data@2026-01-01

# проверка целостности
sudo zpool scrub tank
zpool status tank

Скраб гоняй раз в месяц через cron или systemd-timer. Он читает все блоки и чинит повреждения по контрольным суммам.

RAIDZ

СхемаДискиПереживаетЁмкость
stripe1+0 отказов100%
mirror2+150%
RAIDZ13+1(n-1)
RAIDZ24+2(n-2)
RAIDZ35+3(n-3)

Для 4+ дисков бери RAIDZ2: пока идёт rebuild, второй диск тоже может умереть. Для двух дисков — зеркало.

3-2-1

  • 3 копии данных.
  • 2 разных носителя.
  • 1 копия вне дома.

RAID — это не бэкап. Он спасает от смерти диска, но не от rm -rf, шифровальщика и пожара.

Бэкап на внешний диск

sudo zfs snapshot tank/data@backup
sudo zfs send tank/data@backup | sudo zfs receive backup/data

# инкрементально
sudo zfs send -i tank/data@backup tank/data@now | sudo zfs receive backup/data

Внешний диск держи выключенным между бэкапами — так его не заденет шифровальщик.

Проверяй восстановление

Бэкап, который никогда не разворачивали, — не бэкап. Раз в квартал восстанавливай файл из копии и убеждайся, что он читается.
