Мониторинг

Быстрая проверка состояния сервера: CPU, ОЗУ, диски, сеть, логи.

Мониторинг отвечает на вопросы «что сломалось», «когда» и «почему». Prometheus собирает метрики, node_exporter отдаёт их с сервера, Grafana рисует графики. Всё локально, без облака.

Установка

Prometheus и node_exporter ставятся из бинарников или пакетов. Пример на Debian:

sudo apt install prometheus prometheus-node-exporter
sudo systemctl enable --now prometheus prometheus-node-exporter

Проверка: http://192.168.0.x:9090 — веб-интерфейс Prometheus, http://192.168.0.x:9100/metrics — метрики узла.

scrape_config

# /etc/prometheus/prometheus.yml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: node
    static_configs:
      - targets: ["localhost:9100"]
  - job_name: proxmox
    static_configs:
      - targets: ["192.168.0.10:9100"]
sudo systemctl reload prometheus

В Status → Targets должно быть UP. Если DOWN — проверь фаервол и порт.

Grafana

sudo apt install grafana
sudo systemctl enable --now grafana-server

Открой http://192.168.0.x:3000, смени пароль admin. Добавь datasource: Configuration → Data Sources → Prometheus, URL http://localhost:9090.

Первый дашборд

Импортируй готовый дашборд node_exporter (ID 1860) или собери свой. Полезные запросы:

# загрузка CPU
100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# свободная память, ГБ
node_memory_MemAvailable_bytes / 1024 / 1024 / 1024

# место на корне, ГБ
node_filesystem_avail_bytes{mountpoint="/"} / 1024 / 1024 / 1024

Алерты

В Prometheus — правило, в Alertmanager — маршрут. Минимальный набор:

  • диск заполнен > 85%;
  • сервис недоступен > 2 минут;
  • нагрузка CPU > 90% пять минут подряд.
