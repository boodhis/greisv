Бекапы: Защита данных

Бекап — это копия важных данных. Если диск сломается или файлы удалят случайно, бекап спасёт.

Правило 3-2-1

  • 3 копии данных
  • 2 разных типа носителей
  • 1 копия вне дома

Простой бекап через rsync

# Бекап домашней директории
rsync -av --progress /home/iva/ /mnt/storage/backups/home/

:::tip[Разбор команды]
- `rsync` — утилита для синхронизации файлов
- `-a` — архивный режим (сохраняет права, даты)
- `-v` — подробный вывод
- `--progress` — показывать прогресс
:::

### Бекап через tar

Создание архива

tar -czvf /mnt/storage/backups/home-$(date +%Y%m%d).tar.gz /home/iva/

Извлечение архива

tar -xzvf backup.tar.gz -C /home/iva/ ```

Разбор команды

  • -c — создать архив
  • -z — сжать gzip
  • -v — подробный вывод
  • -f — имя файла

Автоматический бекап (cron)

# Редактирование cron
crontab -e

# Добавь строку (бекап каждый день в 3:00)
0 3 * * * rsync -av /home/iva/ /mnt/storage/backups/home/

Разбор команды

  • 0 3 * — каждый день в 3:00
  • crontab -e — редактирование расписания задач

Бекап базы данных

PostgreSQL

# Бекап базы
pg_dump -U username database_name > backup.sql

# Восстановление
psql -U username database_name < backup.sql

SQLite

# Простое копирование файла
cp /path/to/database.db /backup/path/

Проверка бекапов

# Проверить размер бекапов
du -sh /mnt/storage/backups/*

# Проверить последний бекап
ls -la /mnt/storage/backups/

Перенос большой библиотеки (rsync + tmux)

Когда данных сотни гигабайт, работа не влезает в одну команду: копирование идёт часами, сессия рвётся от срабатывания таймаута — и копия теряется с середины. Правильный способ: запустить копирование в tmux, чтобы оно жило независимо от твоего подключения.

# запустить или вернуться в tmux-сессию
ssh -t server "tmux a || tmux"

# внутри tmux — сама копия (например, перенос библиотеки с minis на новый диск)
sudo rsync -avP /mnt/minis/ /mnt/2tb/

Разбор команды

  • tmux a — подключиться к предыдущей сессии, tmux — создать новую
  • -P — показывать прогресс и поддержать возобновление прерванной копии
  • Ctrl+B, затем D — отцепиться, оставив копию работать

После копирования: вернуть зарезервированные системой 5% места — sudo tune2fs -m 0 /dev/sdX1, затем остановить контейнеры, переставить диски и обновить пути в docker-compose.yml.
