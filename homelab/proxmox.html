Proxmox VE

Виртуальные машины (VM) и контейнеры (LXC) для homelab.

Proxmox VE — гипервизор на Debian с веб-интерфейсом. На одном сервере — виртуалки, LXC-контейнеры, бэкапы и снапшоты. Заменяет VMware в домашней лаборатории без лицензий.

Установка

  1. Скачай ISO Proxmox VE, запиши на флешку.
  2. В BIOS включи виртуализацию (VT-x/AMD-V).
  3. Загрузись с флешки, выбери диск, задай hostname и пароль root.
  4. Сеть: статический IP, шлюз, DNS. Адрес откроется по https://192.168.0.x:8006.
  5. После установки подключись по SSH и обнови: apt update && apt full-upgrade.
Репозитории

Из коробки включён enterprise-репозиторий, требующий подписки. Для дома отключи его и включи pve-no-subscription в /etc/apt/sources.list.d/.

Дашборд

Слева — дерево: узел, VM, LXC, хранилища. Сверху — нагрузка CPU/RAM и графики. В Datacenter → Permissions создай пользователя вместо работы под root.

Создание VM

  1. Загрузи ISO в local → ISO Images (или через ссылку, если есть интернет).
  2. Create VM: имя, ID, тип ОС.
  3. Диск: шина VirtIO SCSI, кэш Write back, размер 20–32 ГБ.
  4. CPU: 2–4 ядра, тип host для производительности.
  5. Память: 2–4 ГБ, отключи Ballooning, если нужен стабильный отклик.
  6. Сеть: vmbr0, модель VirtIO.
  7. После установки — qemu-guest-agent внутри гостя для корректного шатдауна.

LXC

Контейнеры легче: без своего ядра, делят ресурсы хоста. Идеальны под nginx, базы, домашние сервисы.

  1. local → CT Templates → скачай debian-12-standard.
  2. Create CT: hostname, пароль, шаблон.
  3. Диск 8 ГБ, RAM 512 МБ, 1 ядро.
  4. Сеть — DHCP или статический IP в vmbr0.
  5. Особенности: unprivileged по умолчанию; для монтирования NFS включи Features → NFS.

Бэкапы и снапшоты

# вручную через CLI
vzdump 100 --storage backup --mode snapshot --compress zstd

# расписание: Datacenter → Backup → Add
# хранение: keep-last 7, keep-weekly 4
ТипКогда использовать
Snapshotбыстро откатить перед обновлением; не заменяет бэкап
vzdumpполный бэкап VM/CT на хранилище
Replicationкопия на второй узел кластера

Хранилища

В Datacenter → Storage добавь NFS/SMB-шару или локальный диск под бэкапы. Для бэкапов лучше отдельный физический диск — см. ZFS и 3-2-1.

Снапшот ≠ бэкап

Снапшот живёт на том же диске, что и VM. Умер диск — умерли и снапшоты. Держи vzdump на другом носителе.
