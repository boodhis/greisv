Сервер

Критерии выбора домашнего сервера: энергопотребление, шум, надёжность, расширяемость.

Домашний сервер — это не «одна большая машина», а набор ролей: файлы, DNS, контейнеры, VPN, мониторинг. Поняв роли, проще выбрать железо и не смешивать всё в кучу. Здесь — карта ролей, требования и автозапуск.

Системные требования

  • CPU: 4 ядра минимум, 8 — комфортно. VT-x/AMD-V обязателен.
  • RAM: 16 ГБ для начала, 32 ГБ если держишь несколько VM.
  • Диск: SSD под систему и VM, HDD под бэкапы и медиа.
  • Сеть: гигабит, статический IP или резервация на роутере.

Автозапуск

Порядок важен: сначала хранилище и сеть, потом сервисы.

# Proxmox: VM/CT стартуют при загрузке
# Datacenter → VM → Options → Start at boot
# On boot order: 1, 2, 3

# внутри LXC — systemd
sudo systemctl enable --now nginx
sudo systemctl enable --now wg-quick@wg0

Для compose-стека:

# /etc/systemd/system/app.service
[Unit]
Description=app compose stack
After=network-online.target docker.service
Requires=docker.service

[Service]
WorkingDirectory=/srv/app
ExecStart=/usr/bin/docker compose up
ExecStop=/usr/bin/docker compose down
Restart=on-failure

[Install]
WantedBy=multi-user.target

Разделение ролей

Одна роль — один LXC/VM. Падает nginx — Docker-стек продолжает работать. Обновляешь Prometheus — не трогаешь VPN. Это дороже по RAM, но дешевле по нервам.

Именование

Держи понятные имена: ct-nginx, ct-dns, vm-docker. Через год ты не вспомнишь, что такое test2.

Не выставляй сервисы в интернет

Наружу — только VPN-порт. Всё остальное доступно внутри сети через WireGuard и nginx.
